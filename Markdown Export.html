0.1 Icarus flow (compile → run → view)

Step Command What it does
Compile iverilog -o sim design.v tb.v Compiles all files into executable sim (vvp bytecode). -o = output name
Run vvp sim Runs the simulation; prints $display/$monitor; writes the .vcd
View gtkwave wave.vcd Opens waveform viewer
Standard iverilog -g2012 -o sim ... Pick language generation (-g2005, -g2012)
Top module iverilog -s tb -o sim ... -s = choose top-level module
Warnings iverilog -Wall ... Enable all warnings
  • Default output if -o omitted: a.out. Compile errors → no executable. The .vcd file name comes from $dumpfile("name.vcd"), not from -o.
  • Simulation ends at $finish; without it (and with an endless always #5 clk=~clk) simulation runs forever.

0.2 Core syntax

`timescale 1ns/1ps          // time unit / precision

module name (input a, b, output y);   // ANSI-style ports
  wire w1;                            // net: driven by gates / assign
  reg  r;                             // variable: assigned in initial/always
  and  g1 (w1, a, b);                 // gate primitive: OUTPUT FIRST, then inputs
  assign y = w1 | a;                  // continuous assignment
endmodule
Item Rule
Gate primitives and or not nand nor xor xnor buf — first terminal is output
Number literals <size>'<base><value> → 4'b1010, 8'hFF, 16'd25; unsized decimals are 32-bit
Vectors wire [7:0] a; → bit 7 is MSB; a[3] bit-select; a[3:0] part-select
Concatenation {a, b}; replication {4{1'b1}} = 1111
Logic values 0, 1, x (unknown), z (high-impedance)
Bitwise & | ^ ~ ~^
Logical && || ! (result 1 bit)
Reduction &a |a ^a (reduce vector to 1 bit)
Conditional s ? a : b
Shift << >>
Equality == (x if any x) vs === (case equality, exact match incl. x/z)
Blocking = Executes in order — used in testbench initial / combinational always
Non-blocking <= Scheduled, updates at end of time step — used for clocked (sequential) logic

0.3 Testbench skeleton

`timescale 1ns/1ps
module tb;
  reg  a, b;            // DUT inputs  -> reg
  wire y;               // DUT outputs -> wire

  my_design dut (.a(a), .b(b), .y(y));   // named port connection

  initial begin
    $dumpfile("wave.vcd");   // output file for GTKWave
    $dumpvars(0, tb);        // dump all signals in tb (0 = all levels)
    $monitor("t=%0t a=%b b=%b y=%b", $time, a, b, y);
    a=0; b=0; #10;
    a=0; b=1; #10;
    a=1; b=0; #10;
    a=1; b=1; #10;
    $finish;
  end
endmodule

$display Print once, when executed (adds newline)
$monitor Auto-print every time any argument changes (one active monitor)
$strobe Print at end of current time step
$time Current simulation time
$finish End simulation ($stop pauses)
$dumpfile / $dumpvars Create VCD / choose signals to record
$random 32-bit signed pseudo-random
Format %b binary, %d decimal, %h hex, %t time, %0d no padding

LAB 2 — Logic Gates and Gate-Level Structural Circuits

Concepts

  • Structural (gate-level) modelling = describe a circuit by instantiating gates/modules and wiring them with wires.
  • Built-in primitives: and, or, not, nand, nor, xor, xnor (also buf). Output is the first terminal. Instance name is optional.
  • Multi-input allowed: and g(y, a, b, c); → y = a·b·c. not/buf have one input (not n(y, a);).
  • Intermediate connections between gates are wires.
  • Verify using an exhaustive testbench: n inputs → 2ⁿ vectors.
Gate Expr Verilog primitive Truth (A,B = 00,01,10,11)
AND A·B and g(y,a,b) 0 0 0 1
OR A+B or g(y,a,b) 0 1 1 1
NOT A̅ not g(y,a) 1 0 (for A=0,1)
NAND (A·B)̅ nand g(y,a,b) 1 1 1 0
NOR (A+B)̅ nor g(y,a,b) 1 0 0 0
XOR A⊕B xor g(y,a,b) 0 1 1 0
XNOR (A⊕B)̅ xnor g(y,a,b) 1 0 0 1

Code

// Simple Circuit-1:  E = ~C,  D = (A·B) + ~C
module circuit1 (input A, B, C, output D, E);
  wire w1;
  and g1 (w1, A, B);   // w1 = A·B
  not g2 (E, C);       // E  = ~C
  or  g3 (D, w1, E);   // D  = w1 + E
endmodule

// Simple Circuit-2:  Y = A + (B·C)
module circuit2 (input A, B, C, output Y);
  wire w1;
  and g1 (w1, C, B);
  or  g2 (Y, A, w1);
endmodule

// Simple Circuit-3:  Z = (A2 + C2·B2) + (B2·A2)
module circuit3 (input A2, B2, C2, output Z);
  wire w1, w2, w3;
  and g1 (w1, C2, B2);
  or  g2 (w2, A2, w1);
  and g3 (w3, B2, A2);
  or  g4 (Z,  w2, w3);
endmodule

Circuit-1 truth table (A B C → E D): 000→1 1 · 001→0 0 · 010→1 1 · 011→0 0 · 100→1 1 · 101→0 0 · 110→1 1 · 111→0 1

LAB 3 — MUX, Decoder, Priority Encoder (Structural)

Concepts

  • MUX: n select lines choose 1 of 2ⁿ data inputs. 4:1 → 2 selects; 8:1 → 3 selects.
  • Decoder: n inputs → 2ⁿ one-hot outputs (exactly one output 1).
  • Priority encoder (8-to-3): highest-numbered active input wins; VALID = 1 if any input is 1.
  • Structural implementation = NOT + AND + OR primitives (SOP form).

4:1 MUX SOP: Y = D0·S1'·S0' + D1·S1'·S0 + D2·S1·S0' + D3·S1·S0

// 4:1 MUX — gate-level
module mux4to1 (input D0, D1, D2, D3, S1, S0, output Y);
  wire ns1, ns0, t0, t1, t2, t3;
  not n1 (ns1, S1);
  not n2 (ns0, S0);
  and a0 (t0, D0, ns1, ns0);
  and a1 (t1, D1, ns1, S0);
  and a2 (t2, D2, S1,  ns0);
  and a3 (t3, D3, S1,  S0);
  or  o1 (Y, t0, t1, t2, t3);
endmodule

// 2:4 decoder — NOT + AND
module dec2to4 (input A1, A0, output Y3, Y2, Y1, Y0);
  wire n1, n0;
  not g1 (n1, A1);  not g2 (n0, A0);
  and g3 (Y0, n1, n0);
  and g4 (Y1, n1, A0);
  and g5 (Y2, A1, n0);
  and g6 (Y3, A1, A0);
endmodule

// 3:8 decoder from two 2:4-style stages (or 8 three-input ANDs)
module dec3to8 (input A2, A1, A0, output [7:0] Y);
  wire n2, n1, n0;
  not (n2,A2); not (n1,A1); not (n0,A0);
  and (Y[0], n2, n1, n0);  and (Y[1], n2, n1, A0);
  and (Y[2], n2, A1, n0);  and (Y[3], n2, A1, A0);
  and (Y[4], A2, n1, n0);  and (Y[5], A2, n1, A0);
  and (Y[6], A2, A1, n0);  and (Y[7], A2, A1, A0);
endmodule

// 8:1 MUX built from two 4:1 + one 2:1 (hierarchical)
module mux8to1 (input [7:0] D, input S2, S1, S0, output Y);
  wire ya, yb, ns2, t0, t1;
  mux4to1 m0 (D[0],D[1],D[2],D[3],S1,S0,ya);
  mux4to1 m1 (D[4],D[5],D[6],D[7],S1,S0,yb);
  not (ns2,S2);  and (t0,ya,ns2);  and (t1,yb,S2);  or (Y,t0,t1);
endmodule

LAB 4 — Data-Flow Modelling

Concepts

  • Data-flow modelling = Boolean/arithmetic expressions with continuous assignment assign.
  • LHS of assign must be a net (wire); RHS re-evaluated whenever any operand changes. All assigns are concurrent — order irrelevant.
  • Operators: ~ & | ^ ~^, ?:, {}, << >>, ==.
  • Vectors: wire [3:0] y; — one-hot decoder via 4'b0001 << A.
  • Compose bigger blocks from smaller ones (4:1 from three 2:1 muxes).

Code

// 4:1 MUX — SOP in dataflow
module mux4_sop (input D0,D1,D2,D3,S1,S0, output Y);
  assign Y = (D0 & ~S1 & ~S0) | (D1 & ~S1 & S0) |
             (D2 &  S1 & ~S0) | (D3 &  S1 & S0);
endmodule

// 4:1 MUX — conditional operator
module mux4_cond (input D0,D1,D2,D3,S1,S0, output Y);
  assign Y = S1 ? (S0 ? D3 : D2) : (S0 ? D1 : D0);
endmodule

// 2:1 MUX
module mux2 (input a, b, s, output y);
  assign y = s ? b : a;          // s=0 -> a, s=1 -> b
endmodule

// 4:1 MUX using 2:1 MUXes
module mux4_from_mux2 (input D0,D1,D2,D3,S1,S0, output Y);
  wire m0, m1;
  mux2 u0 (D0, D1, S0, m0);      // first stage uses S0
  mux2 u1 (D2, D3, S0, m1);
  mux2 u2 (m0, m1, S1, Y);       // second stage uses S1
endmodule

// 2:4 decoder — vector, dataflow
module dec2to4_df (input [1:0] A, output [3:0] Y);
  assign Y = 4'b0001 << A;       // A=00->0001, 01->0010, 10->0100, 11->1000
endmodule
// equivalent bit-wise:
//   assign Y[0] = ~A[1] & ~A[0];  assign Y[1] = ~A[1] & A[0];
//   assign Y[2] =  A[1] & ~A[0];  assign Y[3] =  A[1] & A[0];

Concepts

Concepts

LAB 7 — 16-bit ALU

Concepts

  • Inputs i0[15:0], i1[15:0], op[1:0]; outputs o[15:0], carry, overflow.
op Operation
00 ADD i0 + i1
01 SUB i0 − i1
10 AND
11 OR
  • Purely combinational (no clock). carry/overflow are don't-care for logic ops.
  • Two's complement: −B = ~B + 1. So A − B = A + ~B + 1. Reuse the adder: b_eff = i1 ^ {16{op[0]}}, cin = op[0].
  • Signed 16-bit range: −32768 … +32767 (0x8000 … 0x7FFF).
  • Carry = carry out of MSB (unsigned view). Overflow (signed view): operands same sign but result sign differs; equivalently overflow = c15 ⊕ c16 (carry into MSB XOR carry out of MSB).
  • For subtraction, carry = 1 means no borrow.
  • Files / flow: iverilog -o test Lab7_alu.v Lab7_alu_tb.v → vvp test → gtkwave <name>.vcd (name set by $dumpfile).

Code

module alu (input [15:0] i0, i1, input [1:0] op,
            output reg [15:0] o, output reg carry, overflow);
  wire [15:0] b_eff = i1 ^ {16{op[0]}};              // invert B when subtracting
  wire [16:0] sum   = {1'b0, i0} + {1'b0, b_eff} + op[0];   // cin = op[0]

  always @(*) begin
    carry = 1'b0;  overflow = 1'b0;
    case (op)
      2'b00, 2'b01: begin
        o     = sum[15:0];
        carry = sum[16];
        overflow = (i0[15] == b_eff[15]) && (o[15] != i0[15]);
      end
      2'b10: o = i0 & i1;
      2'b11: o = i0 | i1;
    endcase
  end
endmodule

LAB 8 — 32-bit Comparators

Concepts

  • Six comparators on 32-bit A, B: ==, !=, >, >=, <, <=. Each output is 1 bit.
  • For any pair, exactly one of A>B, A==B, A<B is 1.
  • Relations: ne = ~eq, ge = ~lt, le = ~gt, ge = gt | eq, le = lt | eq.
  • Vectors are unsigned by default. For signed: $signed(A) < $signed(B) or declare input signed [31:0].
  • == returns x if any bit is x/z; === compares exactly (including x/z) and returns 0/1.
  • Gate-style equality: eq = &(~(A ^ B)) (all XNORs ANDed) or ~|(A ^ B).
  • Exhaustive testing impossible (2⁶⁴ pairs) → directed corner cases + $random.

  assign ne = (A != B);

  assign ge = (A >= B);

LAB 9 — Register File (8 × 16-bit)

Concepts

  • Why: the ALU can't wait hundreds of cycles for memory; the register file is small, fast storage that feeds the ALU.
  • 8 registers × 16 bits, 2 read ports (a, b), 1 write port. Addresses are 3 bits (0–7).
  • Register 0 is hard-wired zero: reading address 0 → output 0; writing address 0 → ignored.
  • Inputs: clk, reset, wr, rd_addr_a[2:0], rd_addr_b[2:0], wr_addr[2:0], d_in[15:0]. Outputs: d_out_a[15:0], d_out_b[15:0].
  • Write: if wr = 1, at the next posedge regs[wr_addr] <= d_in. If wr = 0, d_in/wr_addr ignored.
  • Read: at the next posedge, d_out_a = contents of register rd_addr_a (same for b). (Synchronous read, as stated in the problem.)
  • Reset = 1: all registers → 0.
  • Structural version: use dfrl (posedge D-FF with reset and load enable, from lib.v) for registers 1–7; per-register load enable = wr & (wr_addr == i) from a 3-to-8 decoder; two 8:1 × 16-bit MUXes for reads. All clk/reset pins connect to the global ones; d_in goes to every register's D.
  • Flip-flop count = 7 × 16 = 112 (R0 needs none).
  • Memory array syntax: reg [15:0] regs [0:7]; (word width first, depth after the name).

Code

// Behavioural version
module reg_file (input clk, reset, wr,
                 input [2:0] rd_addr_a, rd_addr_b, wr_addr,
                 input [15:0] d_in,
                 output reg [15:0] d_out_a, d_out_b);

  reg [15:0] regs [1:7];          // R0 is implicit zero
  integer i;

  always @(posedge clk) begin
    if (reset) begin
      for (i = 1; i < 8; i = i + 1) regs[i] <= 16'b0;
      d_out_a <= 16'b0;
      d_out_b <= 16'b0;
    end else begin
      if (wr && wr_addr != 3'd0)        // write port (R0 ignored)
        regs[wr_addr] <= d_in;
      d_out_a <= (rd_addr_a == 3'd0) ? 16'b0 : regs[rd_addr_a];  // read port a
      d_out_b <= (rd_addr_b == 3'd0) ? 16'b0 : regs[rd_addr_b];  // read port b
    end
  end
endmodule

// read mux:  d_out_a = 8:1 MUX(q0=16'b0, q1 ... q7) selected by rd_addr_a
